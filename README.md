# Personal Trading Journal

Personal Trading Journal is a local-first Windows desktop application designed to help traders record, review, analyze, and improve their trading process. The initial focus is futures trading, especially instruments such as NQ and ES, while the architecture is intended to remain extensible to other markets and a possible future SaaS or web version.

The repository currently contains the application foundation, the core trading Domain model, local EF Core/SQLite persistence, the WPF shell and navigation foundation, persisted System/Dark/Light appearance preferences, complete lifecycle management for Trading Accounts, Instruments, Trading Setups, and Trading Mistakes, and manual Trade create/list/view/edit/close/delete workflows. Trades also support local screenshots, Setup classification, Mistake assignments, an authoritative SQLite-paged and sortable browse view, and reviewed Tradovate matched-fills and Topstep closed-row CSV import workflows. Dashboard and Calendar provide analytics and daily Trade review. The Journal page supports daily text, read-only Trade context, three Daily Review questions, explicit completion/reopening, exact-scope launch from Calendar and paged Review History with read-only durable revisions. Explicit-only AI coaching generation and saved source snapshots are available for future callers; the Daily Review UI remains deferred.

## Current Status

**M15.5 — Saved AI analysis history and source snapshots (no UI yet)**

`GenerateAndSaveCoachingService` returns Saved only after a validated response and the exact M15.3 evidence packet commit atomically to SQLite. Independent, immutable snapshots retain source identities, statistics/coverage, currencies, original Account names, Journal text/status/revisions, UTC generation time, contract versions and allowlisted provider/token metadata. Source edits/deletion never rewrite history. Bounded history selects one New York date and explicit All-accounts or exact-Account analysis scope; deleting one analysis affects no sources or other analyses. The additive `AddCoachingAnalysisSnapshots` migration has no source foreign keys or retention policy. **Snapshots contain sensitive financial and Journal content in the local database/backups, even after source deletion**; no API credential, raw HTTP envelope or error diagnostic is stored. See [history contracts, deletion and privacy](docs/daily-review.md#m155-saved-analyses-and-source-snapshots).

M15.5 local verification: **208 focused tests** and **3,180 full parallel Release tests passed**; Release build has zero warnings/errors and EF reports no pending model changes. The [verification notes](docs/daily-review.md#m155-verification) retain an earlier unchanged Journal WPF timeout and the corrected migration inventory assertions; local green results are not GitHub Actions or live UI acceptance.

**M15.4 — Explicit AI generation service (no UI yet)**

`DailyCoachingGenerationService.GenerateAsync(packet, cancellationToken)` submits one complete M15.3 packet through a provider-neutral interface and returns coaching only after full structure, fingerprint and source-reference validation. The initial OpenAI Responses adapter pins `gpt-4.1-mini-2025-04-14`, uses strict structured output, disables response storage/truncation, and never automatically retries. Registration, local reads, Journal saves and refreshes do not generate anything. Credentials come from `OPENAI_API_KEY` at explicit invocation only; never put keys in source, settings files or the database. No prompts/source text/responses are logged. Defaults: 90-second deadline, 8,192 output tokens, conservative 300,000-token input budget. Request/token metadata is returned where available; monetary cost stays unknown without verified pricing. No generation UI, saved analysis, migration or paid test call is included. See [configuration, failure outcomes and privacy limits](docs/daily-review.md#m154-manual-generation-and-openai-provider).

**M15.3 — AI Coaching evidence and response contract**

`CoachingEvidencePacketBuilder` creates an immutable, versioned daily packet from M15.1 evidence and M15.2 calculations, preserving currency/Account boundaries, source IDs, Journal revisions and explicit missing-data states. Calculated facts, recorded Trades and untrusted user-written Journal observations remain separate. Complete packets are capped at 256 KiB of escaped UTF-8 JSON; oversized evidence is rejected without truncation. A structured response validator checks version, packet fingerprint, bounded sections and valid source citations without claiming to prove the prose true. No provider call, UI, generated coaching, analysis storage or database change is added. See [coaching boundary and limitations](docs/daily-review.md#m153-coaching-evidence-and-response-contract).

**M15.2 — Daily Review statistics and data quality**

`DailyReviewStatisticsCalculator.Calculate(evidence)` adds pure, deterministic Gross and strict verified-Net outcomes over the M15.1 snapshot. It reuses Dashboard/Calendar formulas, partitions by historical currency and Account, and exposes contributing Trade IDs, coverage, unknown commissions/fees and excluded open/partial activity. A complete Net total or ratio requires all closed Trades' authoritative Net and known costs; no Gross-as-Net estimate or cross-currency total is supplied. Empty and unavailable results remain distinct from genuine zero. No UI, AI generation, writes or migration are introduced. See [metric definitions and limits](docs/daily-review.md#m152-statistics-and-data-quality).

**M15.1 — Daily Review scope and evidence**

M15 includes Daily Review with AI Coaching. Its first stage adds `IDailyReviewEvidenceReader`: a read-only, consistent SQLite snapshot for one explicit New York date and optional Account filter. Fully closed Trades use Calendar's closure-date attribution; open/partial Trades with activity that day are separately marked context. All accounts retains every original Account identity, including null-scoped Journals. Evidence preserves source/execution IDs, nullable costs and P&L, historical currency, classifications, Journal fields/status/revision and data-quality flags. Four batch queries avoid per-Trade reads and browse-page truncation. No UI, AI calls, generated interpretation, analysis persistence or migration is added. See [Daily Review contract and limits](docs/daily-review.md).
