# Repository Instructions

## Keep the README current

After any major or important change, update `README.md` as part of the same task or pull request, before considering the work complete. This applies to significant features, user-visible behavior changes, architecture changes, setup or configuration changes, developer workflows, and project status or limitations.

- Update the relevant overview, features, status, quickstart, architecture, testing, or documentation sections to reflect the actual implementation.
- Keep the README concise, professional, and focused on helping users understand and run the project.
- Put detailed milestone history, diagnostics, and verification evidence in the appropriate `docs/` guide or `docs/development-history.md`, and link to it from the README when useful. Do not turn the README back into a running development log.
- Distinguish implemented functionality from planned work and pending verification. Do not claim tests or acceptance passed without supporting evidence.
- Check affected links, anchors, and command examples after editing.

Minor internal refactors or cosmetic changes do not require a README update unless they make its existing content inaccurate.
